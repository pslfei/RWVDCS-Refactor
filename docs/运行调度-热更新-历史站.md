# 运行调度 / 块热更新 / 内嵌历史站

> 本文对应 M4/M5 收尾开发（连续运行 + 稳定性监测 + Roslyn/ALC 热更集成 + 历史站最小闭环），
> 与《工况快照与wrk迁移》共同构成新系统运行时的完整说明。

## 1. 扫描调度器（ScanScheduler）

老系统是"每 DPU 一个 `System.Threading.Timer`"，回调线程池抢占执行、以 `lock` 兜底重入。
新系统改为**单扫描线程按节拍驱动**（`src/Runtime/RWVDCS.Runtime/ScanScheduler.cs`）：

- 每个 DPU 维护独立的 `nextDue` 到点时刻，按 `dpu.Cycle`（默认 200 ms，与老系统一致）推进；
  同一 tick 内多个 DPU 到点时按装配序串行执行——与对账用的 `runtime.Step()` 执行序完全一致，
  连续运行模式不引入新的不确定性。
- 执行耗时超过周期 → 记一次超限（Overrun）并**重新起拍**（不爆发式追补），对齐仿真机"慢了就慢了"的语义。
- 状态机 `Stopped / Running / Paused`；`Pause()` 返回时保证周期边界；`StepOnce(n)` 暂停态单步；
  `RunAtCycleBoundary(action)` 用于存/取工况、热更换代等结构性操作的原子化。
- 每 DPU 周期统计：cur / min / max / avg / p95 / p99（直方图估算）/ 超限计数，对齐老系统
  `Dpu.CurrentCycleTime/Max/Min/Average` 并有所增强。

REPL：`run` / `pause` / `s [n]` / `stats` / `cycle <秒>`。CLI：`--run N`（连续 N 秒，0=Ctrl+C 停）、
`--soak-steps N`（全速浸泡）、`--monitor N`（采样间隔）、`--stats-csv <文件>`。

## 2. 稳定性监控（StabilityMonitor）

宿主内建进程级采样（`src/Host/RWVDCS.Host/StabilityMonitor.cs`）：
周期统计聚合 + GC 各代次数增量 + 托管堆 / 工作集 / 分配速率（`GC.GetTotalAllocatedBytes`）/
GC 暂停占比（`GCMemoryInfo.PauseTimePercentage`）/ 线程数 / 历史站文件体积。
控制台一行摘要 + 可选 CSV（长跑趋势分析、内存泄漏检测）。

## 3. 功能块热更新（Roslyn + 可回收 ALC，"现调现改"）

链路（`src/Host/RWVDCS.Host/HotLoad.cs` + `src/Runtime/RWVDCS.Runtime/BlockHotSwapper.cs`）：

```
修改 FC_XXX_RUN.cs → KernelCompiler（Roslyn 内存编译，源码内嵌 PDB）
   → BlockHotSwapper.Apply（周期边界内原子执行）：
       新程序集装入可回收 AssemblyLoadContext（每次热更一代）
       按 [FCName] 找到受影响功能码 → 逐命令：
         用装配期同一套 BuildCommand 语义重建命令（绑定/常量/默认值全重建）
         按字段名转移全部状态（管脚 live 值 + 私有内部状态，如 _timing/_prevX）
         清除装配期默认值残留（换代是"继续跑"，不是"重新初始化"）
         原位替换命令表条目
       旧代 ALC Unload（协作式；宿主验证 GC 真回收）
```

REPL：`hotload TIMER`（按功能码名自动配齐 `FC_TIMER.cs` + `FC_TIMER_RUN.cs`）或
`hotload <路径1.cs> <路径2.cs>`；`--blocks-src` 指定源码目录。

关键工程点：

- **状态不丢**：13,506 个 TIMER 实例换代实测转移 216,096 个状态字段，换代前后
  逐点 dump 与"不中断运行"的基线**按位一致**（非确定点除外）。
- **真卸载**：`BlockStateSchema` / `BlockStateCodec` / `FieldAccessor` 三处静态缓存改为
  `ConditionalWeakTable`，旧代类型不被钉住；宿主换代后主动 GC 验证弱引用死亡。
  若某代还有其他功能码在用（本次只换了部分块），该代会延迟到无引用时回收，属正常。
- **约束**：新块类型的状态字节数不得超过装配期 Arena 槽长（新增/扩大字段需完整重启装配）；
  热更改变字段布局后，此前保存的旧工况中该块状态区不再对位，热更后应重存工况。
- 编译毫秒级（首次 ~1 s 是 Roslyn 引用集构建，之后 ~60-100 ms），换代 ~200 ms（13.5k 实例）。

## 4. 内嵌历史站（HistoryRecorder，M4 最小闭环）

方案 §4.5"变化才存 + 死区压缩 + 周期强制存"的落地（`src/Runtime/RWVDCS.Runtime/HistoryRecorder.cs`）：

- 挂在 `ScanScheduler.AfterDpuStep`，每周期扫描 DB 点 buffer（不含中间 pin-point）。
- LA 死区 = 量程 × 0.1%（量程无效退化为绝对死区 1e-6）；LD/LP/LP32 按位变化才存；
  每点最多 300 周期强制存一笔（200 ms 周期 = 1 分钟），保证冷点也有基线。
- 每 DPU 一个追加式帧日志（`<会话目录>/<DPU>.rwhist`）：
  `帧头(cycle, unixMs, count) + count × (sid, float)`，进程中断只丢尾帧。
- 会话目录按启动时间命名，不覆盖历史会话。
- 实测（50 DPU / 289k 点 / 200ms 节拍）：全量扫描 ~1-2 ms/周期/全部DPU，
  5 分钟连跑历史文件合计 ~6 MB——变化率决定体积，远小于全量快照流。
- 查询：REPL `hist <点名> [n]`（顺序扫描解码）；`HistoryRecorder.Query` 可供工具离线读取。

尚未做（后续里程碑）：分段压缩（zstd）、按时间索引、死区/间隔的按点配置表、IoTDB 可选镜像。

## 5. 实测稳定性基线（2026-07-06，开发机，Release）

工程：真实项目 mdb（50 DPU / 123,692 DB 点 + 165,569 中间点 / 196,779 命令 = 289,261 数据点）。

### 5.1 节拍连跑 30 分钟（200 ms 周期，含历史站，`--run 1800`）

- 周期总数 450,050（50 DPU × 9,001），聚合 50.0 周期/s **零漂移**；**超限 0 次**。
- 单周期耗时（50 DPU 串行合计）：平均 3.71 ms（周期预算 200 ms 的 1.9%）；
  p99 = 10 ms；最大 44 ms（仅启动 JIT 阶段）。
- 内存：托管堆 642.6 → 643.7 MB（30 分钟 **+1.1 MB**，无泄漏趋势）；工作集稳定 ~900 MB。
- GC：gen1=15 / gen2=9 全部发生在启动首分钟，之后 30 分钟**零 gen1/gen2**；
  gen0 ~47/s（分配 ~356 MB/s 的廉价回收）；GC 暂停占比稳态 **0.87%**。
- 历史站：33 MB / 30 min（289k 点，死区 0.1%）；记录扫描 ~1-2 ms/周期已计入上述耗时。
- 终态导出 289,261 点：**无 NaN / Infinity**。
- 原始数据：`out/run-30min.csv`（60 s 采样 × 30 行趋势）。

### 5.2 全速浸泡 10,000 周期（`--soak-steps 10000`，等效节拍模式 33 分钟负载）

- 30.6 ms/周期全速推进（≈ 6.5× 实时）；每 DPU 10,000 周期统计：超限 0。
- 堆 586 MB 首尾持平；周期耗时前后半程无退化（avg 3.51 → 3.47 ms）。
- 原始数据：`out/soak-10k.csv`。

### 5.3 热更换代（13,506 个 TIMER 实例）

- 编译 60-100 ms（首次 ~1 s 为 Roslyn 引用集构建）+ 换代 ~200 ms（含 216,096 个状态字段转移）。
- 同源热更后续跑 10 周期，与"不中断运行"基线逐点对账：**289,247/289,247 一致**（14 个非确定点按规则排除）。
- 改逻辑热更（时间步长 ×2 探针）：换代后 TRun 由 +0.2/周期变为 +0.4/周期，行为立即生效、已累计状态保留。
- 换代后旧代 ALC 经 GC 验证**真回收**（无程序集泄漏）。

已知的后续优化项（非稳定性缺陷）：
输入/输出同步走 `ReadBoxedBuffer` 装箱路径，分配速率 ~356 MB/s（gen0 廉价回收、稳态暂停 <1%，
但值得做类型化直拷快路径，预计可降一个数量级）——列入性能里程碑。
