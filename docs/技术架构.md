# RWVDCS 重构系统技术架构

> 面向开发与运维人员的整体架构说明。配套文档：《操作手册》《部署运维》《工况快照与wrk迁移》《运行调度-热更新-历史站》。

## 1. 总体结构

新系统以 .NET 10 LTS 为基础，替换老系统（.NET Framework 4.7.2 + 自研指针式 RTD + .NET Remoting）。
核心设计取向：**托管安全内存（无 unsafe 指针）、确定性执行、按名迁移的状态兼容、REST/SSE 对外服务**。

## 2. 数据面：PointArena

老系统 RTD 用 `Marshal.AllocHGlobal` + unsafe 指针手工管理内存；新系统改为 **MemoryMappedFile 支撑的连续 Arena**（`PointArena`）：

- 每 DPU 一个 Arena：`名字表 + 槽描述表 + 数据区` 三段连续布局，槽号（SID）即索引，点名在装配期一次性 map 到 SID，运行期全部按 SID/Span 访问，无字符串查找、无指针。
- 点类型 `LA`（模拟量 float）/ `LD`（数字量 bool）/ `LP`（uint16）/ `LP32`（uint32）是 `struct`，含 buffer/强制/品质等子字段，布局由 `PointLayout` 统一管理；功能块状态占用 Block 槽（`BlockStateSchema` 反射布局 + 表达式树编解码，一次生成缓存）。
- Arena 可选 MMF 文件后备（`--arena` 目录）：进程崩溃后数据区仍在文件里，也为快照提供了"整段 memcpy"级的读取面。
- `SchemaHash`：装配结束后对"槽名+类型+长度"序列做哈希——两次构建 SchemaHash 相同 ⇒ 布局逐字节相同 ⇒ 快照可整段回放；不同 ⇒ 走按名兼容转换。

## 3. 工程面：mdb 直读与指纹

- `MdbEngineeringReader` 用 `System.Data.OleDb`（ACE 12.0）直读 Access 工程库，**不再走 NHibernate**；
  行序、重名、大小写语义与老系统逐条对齐（自然行序 = 老系统装载序，详见《05 工程装载语义规格》）。
- 表约定：`Cld_` 前缀 = Control Logic Document（控制逻辑文档），如 `Cld_FCBlock`（块）、`Cld_FCInput/Cld_FCOutput`（管脚）；`Cfg_VarSystem`（点表）；`Prj_Controller`（控制器/DPU）。
- **工程指纹**（`ProjectFingerprint`）：对纯净工程模型（未经装配改写）的规范化序列做 SHA-256，取前 16 hex。
  指纹是工况/快照兼容性判定和版本档案的锚点。
- **模型差异**（`ModelDiff`）：老 vs 新工程按控制器→点→块→管脚逐级按名比对，产出
  `PointAdded/Removed/Changed、BlockAdded/Removed/TypeChanged/WiringChanged/ParamChanged` 差异清单，
  语义对齐成熟 DCS 的下装预检报告（DeltaV download-with-verify / CODESYS online change 变更清单）。

## 4. 运行时核心

### 4.1 装配（RuntimeBuilder）

纯净模型 `Clone()` 后交给装配器（装配会就地改写 pin 的 PointName 追加、粘滞取反等）：

1. pin-point 预处理：`块名.管脚名` 式引用注册中间点、源块输出追加（对齐老 `Dpu.cs` 语义；源块不存在 ⇒ 整 DPU 命令装配失败，与老系统抛异常等价，但**点仍保留**）；
2. Arena 槽规划：DB 点 → 中间点 → 块状态槽，一次性 `PointArena.Create`；
3. 逐块构造命令（绑定解析、常量、默认值），单块失败跳过（老系统同语义）；
4. 全局接线解析：跨 DPU 名字表首见生效；
5. 生成"基线镜像"：装配初值数据区的 Brotli 压缩副本，作为增量快照的参照系。

### 4.2 调度（ScanScheduler）

单扫描线程按各 DPU 独立节拍驱动，见《运行调度-热更新-历史站》。
状态机 `Stopped/Running/Paused`：`Paused` 可单步（`StepOnce(n)`）；`Pause()` 在 Stopped 态也可进入
Paused（"就绪待单步"——下装/工况加载后恢复暂停态用）。所有结构性操作（存/取工况快照、下装切换、热更）
经 `RunAtCycleBoundary` 在周期边界原子执行。

### 4.3 在线下装（OnlineDownloader，两阶段）

参考成熟 DCS/PLC 运行时（DeltaV、CODESYS online change）设计的 **prepare → commit** 两阶段协议：

```
prepare(新mdb)
  ├─ 读新工程 → 算指纹 → ModelDiff 差异清单（增删改/破坏性标记）
  ├─ 静态预检：悬空 pin 引用检查（引用不存在源块 ⇒ 该 DPU 会整体装配失败）
  │    有致命问题 ⇒ 计划带 Errors，commit 直接拒绝
  └─ 产出 DownloadPlan（planId，含纯净新模型）

commit(planId)
  ├─ （可选）自动备份当前工况
  ├─ 新工程完整重建（旁路构建，旧运行时继续跑）
  ├─ 构建验证：旧 DPU 有命令而新 DPU 命令清零 ⇒ 拒绝切换，旧系统原样继续
  ├─ 周期边界：OnlineDownloader.Transfer 状态按名迁移
  │    点：按名+类型匹配 → buffer/强制/品质全量拷贝（类型变更→丢弃计数）
  │    块：按名+功能码匹配 → 状态字段按名转移（跳过装配常量，保新参数生效）
  │    强制表随点/管脚携带
  └─ 原子切换 SwapRuntime → 恢复原运行态（Running→Running，Paused→Paused）
       版本档案 +1（source=download）
```

失败面处理：预检拦截（悬空引用）→ HTTP 400；构建验证拦截（DPU 命令清零）→ 放弃新运行时、旧系统不动；
迁移在周期边界内串行执行，不存在中间态可见性问题。

### 4.4 热更（BlockHotSwapper）与历史站（HistoryRecorder）

见《运行调度-热更新-历史站》。热更是**同工程内换功能码实现**（Roslyn + 可回收 ALC + 状态按名转移）；
下装是**换工程**（重建 + 迁移）。两者共享"按名转移状态"的底层语义。

### 4.5 交叉引用（XrefIndex）

装配完成后一次性建索引：`点名 → 生产者管脚列表 + 消费者管脚列表`（大小写不敏感）。
支撑 Web UI 的"输入引脚跳源头 / 输出引脚列使用方"导航。运行时切换（下装/工况加载）后自动重建。

## 5. 持久化体系

三层持久化，详细格式见《工况快照与wrk迁移》：

| 层 | 内容 | 兼容性 | 典型体积/耗时 |
|---|---|---|---|
| **快照**（SnapshotV2） | 变化槽位增量（vs 装配基线），Brotli 压缩 | 同指纹整段回放；跨指纹按名兼容转换（点按名+类型、块按名+SchemaHash 直拷/字段级转换） | ~27 MB / 1-2 s（30万点+19万块） |
| **工况**（Condition） | 内嵌工程库副本（mdb 原样拷贝）+ 全量 Arena 镜像 | 自包含——任何时候可完整重现该时刻的工程+状态 | ~370 MB / 7-8 s |
| **版本档案**（versions.json） | 指纹、来源（load/download/condition）、时间、mdb 路径 | 工程演化的审计链 | KB 级 |

**工况 vs 快照**的语义区分（与老系统一致并强化）：工况含工程信息可跨工程恢复；
快照假定工程不变、只存变化数据，因此保存/加载都快一个数量级。
工程变更后老快照不失效——加载时指纹不匹配自动进入**兼容转换**（点按名恢复、块 SchemaHash
相同直拷、不同则字段级按名转换、删除的块跳过），转换统计随响应返回。

## 6. 服务面

### 6.1 REST + SSE（ApiServer，Kestrel）

`/api/*` 全家桶：状态/装载、运行控制（start/pause/step/stop）、DPU 列表与周期设置、点/块分页检索、
点值读写/强制、块管脚/参数/内部变量读写与强制、批量读写（`/values/read|write|describe`，教练员站与适配器用）、
工况/快照 CRUD、下装 prepare/commit、热更、版本档案、Xref、日志（`/logs` + `/logs/stream` SSE）。
错误统一 `{ "error": "..." }` + 4xx/5xx。

### 6.2 Web 管理台（wwwroot 静态 SPA）

零构建链（原生 HTML/CSS/JS，hash 路由）：总览（装载入口/运行控制/监控）、DPU 列表（周期单独/统一设置）、
点块浏览（搜索/类型筛选/收藏）、PointInfo（分 tab：输入/输出管脚、参数、内部变量；强制/写值/交叉引用跳转）、
工况快照管理、在线下装（差异报告+预检错误展示+提交）、版本档案、实时日志。

### 6.3 Remoting 兼容适配器（net48 x86）

.NET Core/.NET 5+ 已移除 .NET Remoting，老客户端（HMI/IOMAP/Alarm）过渡期通过独立适配器进程接入：

```
老客户端 ──TCP/IPC Remoting(BinaryFormatter, port 8000, URI "Communication")──▶
  RemotingAdapter（引用老 PS.Comm.dll 保证二进制契约兼容）
    ICommunication/IEdit/IConsole 实现 → RestBridge（同步 HTTP）→ 新系统 REST
    SubscriptionRegistry 后台轮询变化 → ICallBack.InformDataChange 推送
```

适配器是**纯无状态转发**（订阅注册表除外），可随时重启；功能验证完成后整层移除，
客户端改连 REST/SSE。

## 7. 并发模型（全局契约）

- **扫描线程**独占 DPU 步进；控制操作经 `RunAtCycleBoundary` 周期边界串行化；
- **结构锁**（`RuntimeHost._structureLock`）串行化装载/下装/工况加载等换运行时操作；
- **点值读写不加锁**：4 字节对齐的 buffer 读写在 x64 天然原子（与老系统 Remoting 写入行为一致）；
- 日志环形缓冲、订阅注册表内部自锁；SSE 广播无锁快照遍历。

## 8. 与老系统的对账结论

- 106 功能码、50 DPU、123,692 点 + 165,569 中间点、196,779 块的真实工程：
  装载 + FirstRun 后**逐点 bit 级一致**（非确定点除外，白名单机制）；
- 10,000 步连续对账零漂移；wrk 迁移工具（LegacyRunner --export-state → 桥接导入）打通；
- 性能基线：装载 ~9 s（老系统分钟级）、50 DPU 全步进 ~35 ms/周期、
  快照保存 1.5 s / 加载 2 s（老系统 wrk 保存分钟级）、30 分钟连跑 GC 暂停占比 <0.1%。
