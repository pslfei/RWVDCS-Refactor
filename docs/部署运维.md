# RWVDCS 部署运维手册

> 部署要求、启动/服务化、诊断与故障排查。日常操作见《操作手册》。

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 或 Windows Server 2019+ x64 | 主宿主与适配器均为 Windows 目标 |
| .NET 运行时 | .NET 10 Desktop Runtime（x64） | 主宿主 `rwvdcs.exe`（net10.0-windows） |
| .NET Framework | 4.8（系统自带） | 仅 Remoting 适配器/老测试客户端需要 |
| Access OLEDB 驱动 | Microsoft Access Database Engine 2016 Redistributable（**x64**） | 读写 .mdb 工程库（ACE.OLEDB.12.0）。若装了 32 位 Office 需用 `/quiet` 强装 x64 版 |
| 内存 | ≥ 8 GB（50 DPU / 30 万点规模实测工作集 ~2 GB，加载工况峰值更高） | |
| 磁盘 | 数据目录预留 ≥ 10 GB | 工况 ~370 MB/个、快照 ~27 MB/个、历史站按配置增长 |
| 端口 | Web 8090（可改）；适配器 8000（Remoting TCP/IPC） | 仅需按需放行老客户端到 Edge 的 TCP；Edge→Host 为本机命名管道 |

## 2. 构建与发布

```powershell
# 完整构建（仓库根目录）
dotnet build src/Host/RWVDCS.Host/RWVDCS.Host.csproj -c Release
dotnet build src/Tools/RWVDCS.Tools.ApiClient/RWVDCS.Tools.ApiClient.csproj -c Release
# 适配器是 net48，正常 dotnet build 即可（需要 libs/legacy/PS.Comm.dll，仓库已带）
dotnet build src/Compat/RWVDCS.RemotingAdapter/RWVDCS.RemotingAdapter.csproj -c Release

# 发布主宿主（自包含目录拷贝即部署）
dotnet publish src/Host/RWVDCS.Host/RWVDCS.Host.csproj -c Release -o D:\rwvdcs\app
```

部署布局建议：

```
D:\rwvdcs\
  app\                 # publish 产物（rwvdcs.exe + Web 静态资源）
  adapter\             # 适配器产物（rwvdcs-remoting-adapter.exe + PS.Comm.dll）
  data\                # --data 数据目录（工况/快照/版本档案/历史站）
  arena\               # --arena MMF 后备目录（可选）
  logs\                # 重定向的进程日志
  project\             # 工程 mdb
```

## 3. 启动与服务化

### 3.1 交互启动（调试）

```powershell
scripts\start-web.ps1                        # 默认 8090 端口、./rwvdcs-data 数据目录
scripts\start-web.ps1 -Port 8090 -Mdb "D:\项目\睿渥\VDCS(RuiWo)--260615.mdb" -Start
scripts\start-remoting-adapter.ps1           # 默认 8000 → http://localhost:8090
```

Remoting Edge 默认以 `--transport pipe` 运行，必须与 Host 部署在同一台 Windows 机器。启动时应同时看到
`Host 二进制请求管道`和`Host 变化事件管道`连接成功。

管道默认限当前 Windows 用户访问；生产中 Host 和 Edge 必须使用同一服务账号运行（例如都使用 SYSTEM）。
仅在应急时显式执行：

```powershell
scripts\start-remoting-adapter.ps1 -Transport rest
```

Pipe 模式不会在故障时自动降级 REST。Host 重启后 Edge 会通过事件心跳感知断线，自动重建请求/事件管道、会话和订阅。

### 3.2 开机自启（任务计划程序，推荐）

`rwvdcs.exe` 是控制台程序，服务化用系统自带的任务计划程序最简单：

```powershell
# 管理员 PowerShell
scripts\install-service.ps1 -Port 8090 -DataDir D:\rwvdcs\data `
    -Mdb "D:\rwvdcs\project\VDCS.mdb" -AutoStart
# 卸载
scripts\install-service.ps1 -Uninstall
```

脚本注册 `RWVDCS-Web` 计划任务（SYSTEM 账户、开机触发、失败自动重启）。
如需完整 Windows 服务语义（SCM 管控），可用 [NSSM](https://nssm.cc/)：
`nssm install RWVDCS "D:\rwvdcs\app\rwvdcs.exe" "--web 8090 --data D:\rwvdcs\data"`。

### 3.3 停止

Web 模式进程接受 Ctrl+C 或标准输入 `quit` 优雅退出（周期边界停扫描、Dispose 历史站）。
任务计划模式直接 `schtasks /End /TN RWVDCS-Web` 或结束进程——Arena 有 MMF 后备时数据区留存，
但**建议先在界面保存工况**再停机。

## 4. 诊断

### 4.1 一键诊断脚本

```powershell
scripts\diagnose.ps1 [-Url http://localhost:8090]
```

输出：进程存活/内存、`/api/status`（工程/运行态/GC/堆）、DPU 周期统计 Top5、
最近 20 条日志、数据目录占用、常见问题自检（端口占用、ACE 驱动、数据目录可写）。

### 4.2 关键指标与日志

- **Web 界面总览页**：堆内存、工作集、GC 暂停占比（长期 >1% 需关注）、线程数。
- **DPU 周期统计**：P99 接近周期值或超限计数持续增长 ⇒ 逻辑过重或宿主资源不足。
- **运行日志**：`/api/logs?max=200` 或界面日志页；来源分类过滤（下装/工况/快照/热更）。
- 进程级：`rwvdcs.exe` 标准输出重定向文件（脚本默认 `logs\web-<port>.log`）。

### 4.3 常见故障

| 现象 | 原因 | 处置 |
|---|---|---|
| 装载报 `Microsoft.ACE.OLEDB.12.0 提供程序未注册` | 未装 x64 ACE 驱动 | 安装 AccessDatabaseEngine_X64.exe（可 `/quiet` 强装） |
| 端口占用启动失败 | 8090 被占 | `netstat -ano | findstr :8090` 找 PID；换端口或杀进程 |
| 下装预检报"致命引用问题" | 新工程库有悬空 pin 引用（引用了被删的块） | 预检信息给出块/管脚/引用名，回工程数据库修正后重新 prepare |
| 下装 commit 报"验证失败" | 新工程某 DPU 装配后命令清零（预检未覆盖的装配失败） | 系统已自动保持旧工程运行；看日志定位装配错误 |
| 快照加载慢（秒级→十秒级） | 指纹不一致走了兼容转换 | 正常；如需秒级回放，在当前工程重新保存快照 |
| 老客户端连不上适配器 | 适配器未启动 / 端口不通 / 客户端 x64 加载 x86 契约失败 | 适配器控制台日志；确认 8000 放行；老客户端保持 x86 |
| 订阅/写值突然慢 | Edge 被显式启动为 `--transport rest` | 查 Edge 启动日志；生产应为“实时订阅/读写使用本机二进制管道” |
| 请求管道可用但没有变化回调 | 事件管道未连接或被旧 Edge 占用 | 查 Host/Edge 的事件管道日志；心跳正常时旧连接约 1 s 内被释放 |
| 请求和事件管道都持续“操作已超时” | Host 还在运行旧 Debug/旧发布产物，或 Host/Edge Windows 账号不同 | Host 日志必须出现“二进制管道已启动”；比对两端 `Windows 账户`；停止旧 Host，重建并启动新 Release 产物 |
| 老客户端 LoadFile 超时 | 大工况加载 >10 s 超过客户端 Remoting 超时 | 服务端实际已完成；调大客户端 channel timeout 配置 |
| 中文日志控制台乱码 | PowerShell 默认 GBK 代码页 | `chcp 65001`；数据本身是 UTF-8，仅显示问题 |

### 4.4 数据目录维护

```
rwvdcs-data\
  conditions\<名>\   # manifest.json + 内嵌 mdb + Arena 镜像
  snapshots\<名>\    # manifest.json + 每 DPU 增量段
  history\           # 每 DPU .rwhist 死区压缩历史
  versions.json      # 版本档案
```

- 工况/快照删除直接走界面/API（删目录同效）；
- 历史站按 DPU 滚动追加，磁盘紧张时可停机清理 `history\`；
- **备份策略**：定期备份 `conditions\` 与 `versions.json` 即可完整恢复（工况自包含工程库）。

## 5. 升级流程

1. 界面保存工况（升级前恢复点）；
2. 停止宿主与适配器；
3. 覆盖 `app\`（publish 产物）；数据目录不动；
4. 启动 → 装载工况 → 校验版本档案与运行状态。

功能块逻辑小改（不动工程库结构）优先走**热更**（不停机）；
工程库变更走**在线下装**（不重启不丢状态）；仅框架级升级需要停机换程序。
